# §13 · Evolução e melhoria contínua

**QS-42 · RECOMENDA ·** Ciclo planejar → fazer → verificar → agir a cada entrega: o que funcionou vira padrão, o que falhou vira ação corretiva **com dono e prazo**.

**QS-43 · ACEITE ·** Incidente gera análise de causa-raiz. Corrigir o processo que permitiu o defeito, não só o código.

**QS-44 · RECOMENDA ·** Vocabulário preciso no relato de defeito reduz retrabalho:

| Termo | O que é |
| :-- | :-- |
| Engano | A decisão humana que originou |
| Defeito | Onde no código está a causa |
| Erro | Resultado inesperado na execução |
| Falha | O que o usuário viu de errado |

**ES-37 · RECOMENDA ·** Ao fim de cada ciclo: o que manter, o que parar, o que começar. Cada item vira ação com dono e prazo, ou a retrospectiva é teatro.

**QS-38 · ACEITE ·** Fluxo prototipado e aceito antes de implementar tela. Corrigir um desenho é ordens de grandeza mais barato que corrigir tela pronta.

**QS-39 · ACEITE ·** Revisar cada tela contra as heurísticas (§8.7).

**QS-40 · BLOQUEIA ·** Os cinco estados de tela (§8.8) fazem parte da definição de pronto.

**QS-41 · ACEITE ·** Acessibilidade verificada (§8.9) faz parte da definição de pronto.
